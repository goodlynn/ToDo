# Система управления задачами To-Do List с подзадачами

## Описание проекта

Данный проект представляет собой JavaFX-приложение для управления задачами и проектами.  
Приложение реализует органайзер, в котором пользователь может создавать простые задачи, объединять их в проекты, добавлять вложенные проекты и отслеживать общий прогресс выполнения.

Проект разработан в рамках лабораторной работы по теме **паттерн Composite / Компоновщик**.

Главная идея приложения: простая задача и проект имеют общий интерфейс, поэтому с ними можно работать одинаково. Проект может содержать как обычные задачи, так и другие проекты.

---

## Задание

**Система управления задачами To-Do List с подзадачами.**

Органайзер содержит:

- **Листья:** простая задача.
- **Контейнеры:** составная задача или проект.
- **Методы:**
  - `getProgress()`
  - `getTotalTime()`

Простая задача имеет:

- название;
- дедлайн;
- статус;
- планируемое время выполнения.

Проект может содержать:

- простые задачи;
- другие проекты;
- вложенные структуры любой глубины.

---

## Используемый паттерн проектирования

В проекте используется паттерн **Composite / Компоновщик**.

Он позволяет представить задачи и проекты в виде древовидной структуры:

```text
Проект
├── Задача
├── Задача
└── Подпроект
    ├── Задача
    └── Задача
```

Преимущество такого подхода в том, что простая задача и проект реализуют общий интерфейс `TaskComponent`.  
Благодаря этому можно одинаково получать название, дедлайн, статус, прогресс и общее время как у отдельной задачи, так и у целого проекта.

## Описание основных классов

### `TaskComponent`

Общий интерфейс для простой задачи и проекта.

Содержит основные методы:

```java
String getTitle();
double getProgress();
int getTotalTime();
Optional<LocalDate> getDeadline();
TaskStatus getStatus();
```

Также содержит методы для работы с вложенными элементами:

```java
List<TaskComponent> getChildren();
void add(TaskComponent component);
void remove(TaskComponent component);
```

Для простой задачи операции добавления и удаления вложенных элементов запрещены.

---

### `SimpleTask`

Класс простой задачи.

Простая задача содержит:

- название;
- дедлайн;
- планируемое время выполнения;
- статус.

Статус задачи может быть одним из трёх:

```text
NEW          — новая
IN_PROGRESS  — в работе
DONE         — готово
```

Прогресс простой задачи рассчитывается по статусу:

| Статус | Прогресс |
|---|---:|
| Новая | 0% |
| В работе | 50% |
| Готово | 100% |

---

### `ProjectTask`

Класс проекта.  
Проект является контейнером и может хранить внутри себя другие элементы типа `TaskComponent`.

Это значит, что в проект можно добавить:

- простую задачу;
- другой проект;
- проект с вложенными задачами.

Проект автоматически рассчитывает:

- общий прогресс;
- общее время;
- ближайший дедлайн;
- общий статус.

---

## Как рассчитывается прогресс

### Прогресс простой задачи

Простая задача получает прогресс в зависимости от статуса:

```text
NEW         = 0%
IN_PROGRESS = 50%
DONE        = 100%
```

### Прогресс проекта

Прогресс проекта рассчитывается на основе прогресса дочерних элементов.

В улучшенной версии расчёт выполняется с учётом планируемого времени задач:

```text
Прогресс проекта = сумма(прогресс задачи * время задачи) / общее время проекта
```

Пример:

| Задача | Время | Прогресс |
|---|---:|---:|
| Задача 1 | 1 час | 100% |
| Задача 2 | 10 часов | 0% |

Расчёт:

```text
(100 * 1 + 0 * 10) / 11 = 9%
```

Такой подход более корректный, потому что большая задача влияет на итоговый процент сильнее, чем маленькая.

---

## Как рассчитывается общее время

Для простой задачи метод `getTotalTime()` возвращает её планируемое время выполнения.

Для проекта метод `getTotalTime()` суммирует время всех дочерних элементов:

```text
Общее время проекта = сумма времени всех задач и подпроектов
```

Если внутри проекта есть подпроект, то его время тоже учитывается.

---

## Как рассчитывается дедлайн проекта

У простой задачи дедлайн задаётся пользователем.

У проекта дедлайн определяется автоматически как самый ранний дедлайн среди всех вложенных задач.

Например:

| Задача | Дедлайн |
|---|---|
| Задача 1 | 10.06.2026 |
| Задача 2 | 15.06.2026 |
| Задача 3 | 12.06.2026 |

Дедлайн проекта будет:

```text
10.06.2026
```

## Обработка исключений

В проекте реализована обработка исключений как на уровне модели, так и на уровне пользовательского интерфейса.

Проверяются следующие ситуации:

- пустое название задачи;
- пустое название проекта;
- отсутствие дедлайна у простой задачи;
- некорректное планируемое время;
- отсутствие статуса;
- попытка добавить пустой элемент;
- попытка добавить проект внутрь самого себя;
- попытка добавить один и тот же элемент повторно;
- попытка удалить несуществующий элемент;
- попытка добавить подзадачу в простую задачу.

Для ошибок используются собственные исключения:

```java
TaskException
TaskValidationException
InvalidTaskOperationException
```

В интерфейсе ошибки отображаются пользователю через диалоговое окно `Alert`.

## Использование ресурсного файла

В проекте используется ресурсный файл:

```text
messages.properties
```

Он содержит текстовые строки интерфейса:

- названия кнопок;
- заголовки;
- сообщения об ошибках;
- подписи полей;
- сообщения об успешных действиях.

Использование ресурсного файла позволяет отделить текст интерфейса от Java-кода.  
Это делает проект более удобным для поддержки и возможной локализации.

## Индивидуальный дизайн

Для оформления интерфейса используется CSS-файл:

```text
todo.css
```

С его помощью задаются:

- внешний вид основного окна;
- оформление панели задач;
- оформление панели деталей;
- стили кнопок;
- стили сообщений;
- выделение выполненных и просроченных задач.

Интерфейс приложения выполнен в индивидуальном стиле и не является стандартным пустым JavaFX-окном.

## Unit-тесты

В проекте присутствуют unit-тесты для проверки логики композита.

Тесты проверяют:

- создание простой задачи;
- расчёт прогресса простой задачи;
- добавление задач в проект;
- расчёт общего времени проекта;
- расчёт прогресса проекта;
- работу вложенных проектов;
- обработку некорректных операций.

Для тестирования используется JUnit 5.

Запуск тестов:

```bash
mvn test
```

## Запуск проекта

### Требования

Для запуска проекта нужны:

- JDK 21 или выше;
- Maven;
- IntelliJ IDEA или другая IDE с поддержкой Maven;
- JavaFX, подключённый через Maven-зависимости.

---

### Запуск через Maven

В терминале из корневой папки проекта выполнить:

```bash
mvn clean javafx:run
```

---

### Запуск через IntelliJ IDEA

Чтобы запускать проект зелёной кнопкой:

1. Открыть проект в IntelliJ IDEA.
2. Дождаться загрузки Maven-зависимостей.
3. Открыть **Run → Edit Configurations**.
4. Создать конфигурацию **Application**.
5. В поле **Main class** указать:

```text
com.example.lab2.Main
```

6. В поле **Use classpath of module** выбрать модуль проекта.
7. Нажать **Apply**.
8. Запустить проект зелёной кнопкой.

Пользователь может создать проект:

```text
Курсовая работа
```


```text

```

```text
Курсовая работа
├── Написать введение — 100%
├── Сделать диаграмму классов — 50%
├── Реализовать интерфейс — 50%
├── Написать тесты — 0%
└── Документация
    ├── README — 100%
    └── Отчёт — 0%
```

Приложение автоматически рассчитает:

- общий процент выполнения;
- общее планируемое время;
- ближайший дедлайн;
- текущий статус проекта.

## Вывод

Проект демонстрирует применение паттерна **Composite** на примере системы управления задачами.  
Простые задачи выступают листьями дерева, а проекты — контейнерами, которые могут включать другие задачи и проекты.

Такой подход позволяет строить гибкую иерархическую структуру задач и автоматически рассчитывать показатели для всего проекта.
